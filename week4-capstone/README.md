# Predicting Internship Selection Outcomes (Week 4 Capstone)

A beginner-friendly machine learning project that explores which applicant factors are associated with being selected for the NextGenLearners internship, and explains the findings for a non-technical audience.

## Objective
Combine cleaning, exploration and aggregation from Weeks 1–3 with a first machine learning model, then report the results honestly and clearly.

## Dataset
- **Source:** the cleaned applicant data from Week 1 (`applicants_cleaned.csv`, 71 applicants, mock data). 37 applicants had a final decision (Selected or Rejected) and were used for modelling.
- **Simulated features:** `num_skills_listed`, `has_portfolio`, `prior_hackathon_participation` and `statement_quality_score` were **generated by code** (fixed random seed) because no real data of this kind exists. They are **not real historical records**. Three were deliberately made somewhat more favourable for selected applicants, so any pattern the model finds reflects the simulation, not real behaviour.

## Method
1. **Extend** the dataset with the four simulated features.
2. **Prepare** the data: convert Yes/No to 1/0, create the target (Selected = 1), and one-hot encode the domain.
3. **Split** into 80% training and 20% testing data.
4. **Train** a Logistic Regression model.
5. **Evaluate** with accuracy, precision, recall and a confusion matrix.
6. **Interpret** which features mattered most.

## Key Results
- **Accuracy:** 62.5% (5 of 8 test applicants predicted correctly). This equals the score of always guessing "Selected", so the model is not yet better than guessing.
- **Precision:** 100%. Both applicants predicted as Selected really were selected.
- **Recall:** 40%. The model found 2 of the 5 applicants who were actually selected.
- **Strongest factor:** the statement quality score, followed by having a portfolio.
- **Caution:** the test set has only 8 applicants, so these numbers are illustrative of the method, not a guarantee of real-world performance.

## Limitations
Small and partly simulated data, a very small test set, possible bias inherited from past decisions, and the model should support human reviewers, never replace them. See the notebook for details.
